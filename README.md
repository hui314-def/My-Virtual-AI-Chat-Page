# <img src="ico.png" alt="项目图标" width="50">虚拟AI · 暗夜对话 · 灵境投影

一款沉浸式 AI 伴侣聊天网页，融合科幻视觉与深度对话体验，支持角色定制、语音合成、图片生成及多话题管理。

## 📖 项目简介

本项目旨在打造一个不同于普通大模型对话平台的沉浸式 AI 交互空间。在这里，你可以与拥有独立人格的 AI 角色进行深入交流，体验透明气泡、动态背景和数字图腾带来的“灵境”氛围。

项目具有较高的自由度：你可以自由设定角色的名字、人设、头像和对话背景图，调整模型参数（温度、上下文长度等）以生成多样化的回复，可以让 AI 的回复通过语音合成朗读出来，并支持语音输入，打造属于你的专属对话角色人格。对话过程上，你不仅可以直接操作消息框 ，遇到不满意的回复可以删除和重新生成，还可以使用话题管理功能组织对话脉络，随时切换话题场景，并将精彩对话导出为 JSON 或 HTML 文件保存或分享。

## ✨ 主要特性

- 🧭 **新手引导与功能地图** — 首次访问自动弹出 5 步上手引导（可跳过）：配好模型服务 → 创建角色 → 开始对话 → 双击消息操作 → 用话题分段。另有「**功能地图**」按 7 个分类列出站内全部功能与入口，支持关键词搜索与**一键定位**（在界面上高亮对应按钮）。入口：个性化设置 → 新手引导。
- 🎭 **角色定制** — 自定义 AI 角色的名称、性格设定、头像和开场白，打造专属灵魂伴侣。
- 👥 **多智能体群聊（编排者驱动）** — 把你已有的角色**拉进同一个群聊一起聊天**：挑 2~10 个角色建群，之后每一轮由一位「**编排者**」阅读群聊记录后决定**这一刻该由谁开口**（也可设为轮流 / 随机，省一次请求）。支持 `@点名`、**发言途中插话**、以及让 AI 们自己聊起来的**旁观模式**。群成员的人设 / 头像 / 音色 / 模型参数**实时继承自各自的来源对话**——在私聊里改了设定，群里那位角色立刻就变，无需任何同步操作。详见「[👥 多智能体群聊](#-多智能体群聊)」。
- 🖼️ **聊天背景** — 可上传自定义背景图，支持静态背景（图片）和动态背景（视频），配合透明玻璃消息气泡，营造沉浸式视觉氛围。
- 🎵 **背景音乐** — 可上传自定义背景音乐，增强沉浸式听觉体验。
- 🎙️ **语音交互** — 支持语音输入（Web Speech API）及语音合成（TTS），让对话更自然。
- 🧠 **模型兼容** — 原生支持 Ollama 和 OpenAI 兼容 API（如 GPT、DeepSeek 等），可自由切换模型。
- 📚 **话题管理** — 通过“新话题”分隔不同对话片段，便于回溯与切换，支持自动/手动生成话题简介。
- 💾 **数据持久化** — 聊天记录与设置自动保存在浏览器 IndexedDB 中，重启不丢失；支持接入 MySQL 后端实现多设备云同步；图片/视频/音频等资源以文件形式存储（`asset://` 短引用），聊天数据只存引用不存二进制。
- 🔍 **全局搜索** — 快速搜索历史消息和会话，一键跳转定位。
- 📤 **导入/导出** — 支持导出单会话为 JSON 或 HTML 文件（**群聊提供 HTML 导出**，正文含发言人名字与成员配色）；导入入口统一放在侧边栏「新建角色」弹窗里（可导入之前导出的对话 JSON，也可导入角色卡）。
- 🤝 **SillyTavern 角色卡兼容** — 支持导入社区标准角色卡（PNG 内嵌 JSON / JSON 卡，兼容 chara_card v2/v3 与 TavernAI 旧格式），导入后自动应用角色设定、开场白与头像（含头像裁剪），并解析角色卡提示词中的 SillyTavern 宏（详见「🧩 SillyTavern 宏解析」）。
- 🖼️ **AI 图片生成** — 集成 ComfyUI 后端，可根据描述生成图片并自动插入对话。
- 🌓 **暗夜/明亮主题** — 原生支持深色、扩展支持浅色主题，适配不同使用场景。
- ⌨️ **快捷键支持** — 内置常用快捷键（新建对话、新话题、聚焦输入等），且可自定义。
- ✨ **消息框操作** — 双击消息框弹出操作栏，支持消息的删除、引用等功能，实现和微信一样的消息管理方式。
- 📖 **知识库搭建** — 支持docx，pdf，txt等格式的文档上传到知识库和多知识库管理操作。
- 🧠 **长期记忆系统** — 跨会话记住用户的偏好、关系与目标：自动提取事实 → DMAE 生命周期管理（记忆随对话升温/降温、休眠、归档、可唤醒）→ 每轮按相关性注入上下文。支持**角色记忆隔离**（每个角色专属记忆 + 全局用户记忆互不干扰）与**云端同步**（登录后落 MySQL，换设备 / 清缓存不丢；删除走墓碑，离线变更自动补传），并提供可视化管理面板（同步状态、开关、统计、编辑/删除/固定/恢复、手动添加、提取/命中/注入三类日志）。
- 🧩 **SillyTavern 宏解析** — 角色卡提示词（人设 / 附加系统设定 / 示例对话 / 开场白）与「生成开场白 / 生成角色设定」按钮的提示词均支持常用宏：静态宏 `{{char}}` `{{user}}` `{{time}}` `{{date}}` `{{weekday}}` `{{datetime}}` `{{random}}` `{{roll}}` `{{newline}}` `{{pipe}}` `{{//注释}}` `{{charVersion}}`，动态宏 `{{input}}` `{{lastMessage}}` `{{lastCharMessage}}` `{{lastUserMessage}}` `{{firstMessage}}` 随对话实时解析；未知宏原样保留不误伤。
- 💭 **角色内心OS输出** — 提示词注入新增「角色内心OS」选项：开启后角色回复前先输出 `<soul>` 内心独白，前端渲染为可折叠面板（与模型思考过程「🤔」相互独立、可共存）；模型的思考过程与内心OS均不会进入后续模型上下文。
- 💬 **QQ 接入** — 让角色以小号身份在 QQ 群里陪人聊天（个性化设置 → QQ 接入）：选一个角色即可**继承其角色名、人设、角色卡设定与模型参数**，可选启用**知识库**（复用同一套向量库）与**语音合成**（音色取角色设置）。默认只响应 @ 机器人，另有冷却 / 配额 / 抖动三层闸门防刷屏；网页关掉后由后端常驻服务继续回话。详见 [`docs/QQ桥接服务说明.md`](docs/QQ桥接服务说明.md)。
- 🫀 **内隐状态（AI 人格深度）** — 给角色一层「你看得见、对话里看不见」的内心状态：**好感度 ❤0~100、情绪、精力、着装、姿态、所在、关系阶段、未说出口的心事**等。开启后（对话设置 → 内隐状态 → 启用）：
  - **悬浮卡片（只读）**：可拖动、可折叠，实时展示当前状态；标题栏 ⟳ 可手动结算，📈 可看状态时间线（迷你折线 + 逐条记录）。**卡片本身不提供任何修改入口**——改值、锁定字段、回滚、增删字段统一在「对话设置 → 内隐状态」里做，避免误触改坏状态。
  - **注入给角色**：每轮发送前把当前状态写进 system prompt，让语气、距离感、小动作与内心一致（并明确要求不得报出数值）；`🔒 未说出口` 这类字段对用户显示 `？？？`，但仍注入给 AI。
  - **自动演化**：**每轮角色回复结束后**由辅助模型结算一次——只返回需要变化的字段，未返回的字段一律保持不变；好感度单次最多 ±10，数值触顶/触底会被 clamp。
  - **按话题独立**：每个话题各维护一份状态（新话题从默认值开始），切话题即切状态；字段定义（角色级）在所有话题间共享。
  - **自定义字段**：可在对话设置里新增/编辑/禁用/删除自定义状态字段（文本 / 数值 / 枚举 / 标签四类），新增时必须填「给 AI 的说明」——这句话会进提取提示词，决定模型能否正确演化该字段。
  - 状态的读写完全落在本地（随聊天的 IndexedDB + 云同步走话题级增量），不新增后台服务、不新增数据库表。

### 2. 模型服务（Ollama 或 OpenAI 兼容）

#### Ollama 配置（推荐本地部署）

安装 [Ollama](https://ollama.com/) 并拉取模型（推荐安装qwen3.5:9b）。

设置环境变量以允许跨域请求（重启 Ollama 生效）：

```bash
# Windows
set OLLAMA_ORIGINS=*

# Linux/macOS
export OLLAMA_ORIGINS=*
```

默认 Ollama API 地址为 `http://localhost:11434`（指向本地端口），可在网页“个性化设置”中根据实际情况修改。

#### OpenAI 兼容 API

支持任何兼容 OpenAI 格式的 API（如 DeepSeek、智谱等），设置中支持一键切换模型厂商，仅需一次配置 API-Key 即可随意切换，也可以支持在设置中填写自定义 Base URL。

### 3. 语音合成服务（建议）

若需要语音朗读功能，可选择启动 `tts_api.py`、`moss_tts_api.py` 或 `voxcpm_tts_server.py`，三者接口完全兼容（`/voices` `/tts` `/tts/stream` `/clone_voice`），前端无需任何改动。

#### 千问语音合成服务（本地模型，离线可用）

安装以下依赖项

```bash
pip install -r backend_code/requirements/tts_requirements.txt
python backend_code/tts/tts_api.py
```

默认监听端口 5000，支持音色克隆（通过上传参考音频），支持 API Key 鉴权（通过 `.env` 设置 `TTS_API_KEY`）。项目文件夹里已经有我克隆好的音色文件，免费使用

首次启动会自动加载 Qwen3-TTS 模型（可提前下载模型权重，参考 [Qwen3-TTS 官方文档](https://modelscope.cn/models/Qwen/Qwen3-TTS-12Hz-1.7B-Base/summary)）。编辑.env文件输入模型路径QWEN_MODEL_DIR（注意：该模型不支持流式生成，需等待生成完成后再播放音频）

#### MOSS 语音合成服务（第三方模型api推荐）

需要登录 [Mossland](https://mossland.studio/)平台获取 API Key，并在 `.env` 文件中设置 `MOSS_API_KEY`。安装依赖并启动服务：

```bash
pip install -r backend_code/requirements/moss_tts_requirements.txt
python backend_code/tts/moss_tts_api.py
```

默认监听端口 5555，必须设置 API Key 鉴权（通过 `.env` 设置 `MOSS_API_KEY`）。支持**音色设计**（文本描述生成音色，无需参考音频）：前端「音色设计」表单填写描述即可生成试听，MOSS 返回可复用音色时会自动存入音色列表。

⚠️ 注意事项：mossland每天有免费积分额度，当天积分次日清零。所以，第二天使用前需要登录mossland平台签到获取

#### VoxCPM2 本地语音合成服务（本地模型，离线可用）

在 [ModelScope](https://modelscope.cn/models/OpenBMB/VoxCPM2) 下载 VoxCPM2 模型权重，安装依赖并启动服务：

```bash
pip install -r backend_code/requirements/voxcpm_tts_requirements.txt
python backend_code/tts/voxcpm_tts_server.py
```

默认监听端口 5500，**接口与 MOSS 版完全兼容**（`/voices` `/tts` `/tts/stream` `/clone_voice` `/design_voice`），前端无需任何改动。音色克隆将参考音频（3~10 秒清晰人声）提取为音色特征，存入 `backend_code/tts/音色库/*.pt`，之后合成无需原音频（一次编码，永久复用）。支持 SSE 流式合成（边生成边播）。支持**音色设计**：前端「音色设计」表单仅填自然语言描述（如"年轻女性，温柔甜美"）即可凭空生成全新音色（无需参考音频），存入 `音色库/*.vdesc.json`，之后合成时自动应用该描述。可通过环境变量配置模型路径与设备：

⚠️ 注意事项：VoxCPM2 模型较大，流式输出有显卡性能要求，若出现卡顿可尝试降低采样率或使用非流式输出。

```bash
# Windows PowerShell
$env:VOXCPM_MODEL_PATH = "your/path/to/model" 
$env:VOXCPM_DEVICE = "cuda"                              # cuda / cpu（默认自动检测）
python backend_code/tts/voxcpm_tts_server.py
```

### 5. 知识库搭建服务（可选）

若需要搭建知识库，则运行：

```bash
pip install -r backend_code/requirements/knowledge_base_requirements.txt
```

#### 嵌入模型（默认中文模型 bge-small-zh-v1.5）

服务默认加载 `backend_code/knowledge_base/local_model/BAAI--bge-small-zh-v1.5`（**中文模型，512 维**）。

> 早期版本默认用 `all-MiniLM-L6-v2`（英文模型，384 维），中文场景下效果很差：实测同一批中文记忆，
> 英文模型的 L2 命中率只有 56%，而且**无关内容的相似度会越过阈值造成误注入**；换成 bge-small-zh-v1.5 后
> 命中率 100%，无关内容稳定落在阈值之下。英文模型已从仓库移除，**不再需要手动更换**。

| 模型 | 维度 | 体积 | 适用场景 |
|---|---|---|---|
| `BAAI/bge-small-zh-v1.5` | 512 | ~183 MB | **默认**：中文效果好、CPU 也快，通用首选 |
| `BAAI/bge-base-zh-v1.5` | 768 | ~391 MB | 追求更高检索精度、内存充足时 |
| `BAAI/bge-m3` | 1024 | ~2.2 GB | 中英混杂、长文本（8192 长度）；最重，需 `transformers>=4.40` |
| `shibing624/text2vec-base-chinese` | 768 | ~400 MB | 老牌中文模型，效果略逊于 bge-zh-v1.5 |

模型若缺失（新克隆的仓库需要自行下载）：

```bash
set HF_ENDPOINT=https://hf-mirror.com
huggingface-cli download BAAI/bge-small-zh-v1.5 --local-dir backend_code/knowledge_base/local_model/BAAI--bge-small-zh-v1.5
```

**想换其它模型**（`.env` 两种写法，任选）：

```env
KB_EMBED_MODEL=BAAI/bge-base-zh-v1.5                  # 仓库名 → local_model/BAAI--bge-base-zh-v1.5
KB_EMBED_MODEL_DIR=D:\models\BAAI--bge-base-zh-v1.5   # 或直接给绝对路径（优先级更高）
```

**换模型后必须重建向量**：不同模型维度不同（512/768/1024），旧向量无法与新查询向量比较，检索会直接报错。
服务启动时会自动做维度检查并打印修复指引；重建方式二选一：

```bash
# ① 保留文档与记忆原文，只重算向量（推荐；先停掉 knowledge_api 服务）
python backend_code/knowledge_base/reembed_all.py --dry-run       # 预览：列出集合规模与维度
python backend_code/knowledge_base/reembed_all.py --include-kb    # 记忆 + 知识库一起重建

# ② 只清空向量，之后重新上传文档 / 前端点「立即同步」重建记忆向量
curl -X POST http://localhost:5051/admin/reset-collections
```

排查与维护接口：

| 接口 | 作用 |
|---|---|
| `GET /admin/embedding-info` | 当前模型、维度、查询前缀、各集合维度状态 |
| `POST /admin/reset-collections` | 清空全部向量（换模型时用） |
| `GET /admin/repair` | 检查并**自动修复**读不出来的空集合（见下） |

**关于向量库位置**：`PERSIST_DIR` 已锚定到 `backend_code/knowledge_base/chroma_db`（绝对路径）。
早期版本用的是相对路径 `./chroma_db`，会随启动目录变化从而产生两个内容不同的向量库
（换启动方式就像「知识库/记忆向量丢了」）。如需自定义，用 `.env` 的 `CHROMA_DIR`。
若你曾经从仓库根目录启动过，可能残留一个 `<仓库根>/chroma_db`，可用
`python backend_code/knowledge_base/migrate_chroma.py --from <旧库目录> --apply` 合并进来。

> 实现细节：BGE 中文系列官方要求在**查询侧**加指令前缀「为这个句子生成表示以用于检索相关文章：」，
> 文档侧不加。服务已按模型名自动判断（`bge-m3` 不加、英文 bge 加英文前缀、text2vec/m3e 不加），
> 也可用 `.env` 的 `KB_EMBED_QUERY_PREFIX` 手动覆盖。

> ⚠️ 已知边界：chromadb 1.5 的空集合（HNSW 段目录为 0 字节）在进程重启后可能抛
> `Nothing found on disk`，导致知识库列表 / 检索失败。服务启动时会自检并自动重建这类**空**集合
> （内容为零，无数据损失）；有数据的集合不会被自动删除，若真读不出来可用 `reembed_all.py` 重建。

#### 长期记忆的云同步机制

记忆是**逐条可变**的数据（每轮对话都会更新 DMAE 活跃度、沉默计数），所以同步方式与聊天记录不同：

| 关注点 | 做法 |
|---|---|
| 传输粒度 | 按条增量（`PUT /api/memories` 批量 upsert），一轮对话只上传变化的几条 |
| 冲突消解 | 按记录自带的 `updatedAt`(ms) **最新写入胜出**；服务端时间戳不比库里新则跳过 → 重复上传幂等 |
| 离线兜底 | 写操作先落本地 IndexedDB，未确认的变更记入 localStorage 队列（按账号命名空间隔离），联网后自动重放 |
| 删除 | 走**删除墓碑**（`deleted=1`）。避免「离线删除后又被云端拉回来」；墓碑保留 90 天 |
| 换账号 | 本地记忆缓存清空后从云端重新拉取；未上传的队列按命名空间保留，换回原账号会重放，不丢数据 |
| 角色级联 | 删除对话（角色）时，该角色在前端与该账号云端的记忆一并删除（全局记忆不受影响） |
| **不同步的部分** | **三类事件日志**（提取 / 命中 / 注入）仅存本地 —— 属诊断视图，每轮都会新增，同步收益低于开销 |

接口一览（均需登录）：

```
GET    /api/memories                  拉取全部记忆 + 删除墓碑
PUT    /api/memories                  批量 upsert {memories:[...]}
DELETE /api/memories/{id}             删除单条（写墓碑）
DELETE /api/memories?ids=a,b,c        批量删除（写墓碑）
DELETE /api/memories/by-chat/{chatId} 按角色级联删除
DELETE /api/memories-cleanup          清理超过 90 天的墓碑（维护用）
```

记忆面板顶部会显示当前同步状态（已登录 / 未登录 / 待上传条数），并带「立即同步」按钮。

> ⚠️ **本地数据分库说明**：本地 IndexedDB 按账号名称空间分库（游客用 `ChatAppDB`，登录后为 `ChatAppDB_<用户名>`）。
> 首次登录时游客库的聊天记录、设置与长期记忆会自动迁移到账号库。
>
> - **登录状态下**：记忆已备份到 MySQL，清除浏览器数据 / 换设备后登录同一账号即可恢复；
> - **未登录状态下**：记忆只在本机浏览器，清除站点数据会永久丢失（面板会黄条提醒）；
> - 用不同浏览器 / 无痕窗口各自独立，登录同一账号后才会合并到同一份云端数据。
>
> 如果记忆「凭空消失」，先用根目录的 `记忆救援工具.html` 诊断（见下文「记忆数据排查」）。

#### 图片 / 视频 / 音频资源存储（文件系统 + URL 引用）

- 图片、背景视频、背景音乐等二进制资源**不存入 MySQL**，而是落盘到 `ASSET_DIR` 目录（默认 `backend_code/chat_store/assets`，通过 `.env` 的 `ASSET_DIR` 修改，建议放 D 盘等大容量磁盘）；
- 聊天数据里只存 `asset://<id>` 短引用，渲染时自动解析为 `http://<主机>:8001/api/assets/<id>`，浏览器按 URL 缓存，跨设备（局域网内）均可访问；
- 接口：
  - `POST /api/assets` — 图片上传（data URL，需登录）；
  - `POST /api/assets/raw` — 视频 / 音频等大文件二进制直传（需登录，Content-Type 决定扩展名）；
  - `GET /api/assets/{id}` — 匿名读取（`<img>`/`<video>`/`<audio>` 直接引用，id 为随机不可猜）；
- **旧数据迁移**（把库里已有的 base64 图片批量导出成文件并替换为引用）：

  ```bash
  python backend_code/chat_store/migrate_assets.py          # 先预览
  python backend_code/chat_store/migrate_assets.py --apply  # 实际执行
  ```

- 注意：视频 / 音频的**历史本地文件**（此前存在浏览器 IndexedDB 中）无法迁移到服务端，但**新上传的**都会进后端、实现跨设备；资源接口当前为局域网内匿名可读（随机 id 防猜），如需更强鉴权可自行扩展。

## 🧠 记忆数据排查（记忆“消失”了怎么办）

记忆存放在本地 IndexedDB（`memories` / `memories_archive` / `memory_events`），并按账号名称空间分库；
**登录后还会同步到 MySQL**。若记忆面板突然为空，按以下顺序排查：

1. **看记忆面板顶部的同步状态条**：显示「未登录」= 当前只存本机；显示「已登录 xxx」= 已启用云端同步。
   点「立即同步」可手动拉取云端 + 重放本地上传队列，结果会以 toast 提示（新增 / 更新 / 删除条数）。
2. **检查登录状态**：登录与未登录用的是两个库。退出登录后看到的是游客库（可能本来就是空的），
   重新登录原账号即会从云端拉回记忆。
3. **确认后端是否在跑**：云同步依赖聊天存储服务（`http://<主机>:8001`）。后端不可达时记忆仍能正常使用，
   只是不落云；恢复后会自动补传（面板状态条会显示「有未上传的本地变更」）。
4. **用 `记忆救援工具.html` 扫描**：把该文件放在与网站相同的目录，用**与网站完全相同的地址**打开
   （网站是 `http://localhost:8000`，就用 `http://localhost:8000/记忆救援工具.html`）。
   IndexedDB 按「协议 + 域名 + 端口」隔离，用 `file://` 或换成 `127.0.0.1` 都读不到数据。
   工具会列出浏览器中所有库及各库的记忆/日志条数，并支持按 `id` 去重后**跨库复制**（只增不删，可先预览）。
5. **判断是否真的丢了**：若所有库的记忆条数均为 0，说明要么从未成功提取过（看“记忆”面板 → 日志 → 提取
   是否有报错），要么数据已被清理且当时未登录。这两种情况无法恢复，只能重新对话提取。
6. 常见误区：换浏览器 / 无痕窗口看到的是**各自独立**的本地记忆；只有登录同一账号才会归并到同一份云端数据。

> 唯一不同步的是**三类事件日志**（提取 / 命中 / 注入），它们只存在产生它们的那台设备上。

## 👥 多智能体群聊

让**多个已有角色**在同一个群聊里一起说话。它不是为了省事把几段回复拼在一起，而是由一位 **编排者（Orchestrator）** 在每一轮阅读群聊记录后，决定**这一刻该由谁开口**、再由该角色以自己的身份说完。

### 一、怎么建群

1. 点击侧边栏底部「新建角色」旁边的 **👥 群组按钮**（悬停提示「新建群聊（2~10 个角色）」）。
2. 在弹窗里勾选 **2 ~ 10 个**已有角色（候选来自你的角色对话存档），可填群名（留空自动生成，例如「群聊 · Nova / 江雨霞」）。
3. 点「创建群聊」——群聊会出现在左侧「智能体档案」列表里，带群组图标与成员数。

> **两类设置分得很清楚**
> · **角色级**（人设 / 头像 / 开场白 / 音色 / 模型参数）→ 始终**继承自各自的来源对话**
> · **空间级**（背景 / 背景音乐 / 用户画像）→ 属于「群空间设置」，由群聊**独立维护**，初始值跟随**第一个被选中的成员**

### 二、四种「什么时候谁开口」

| 方式 | 说明 |
| :--- | :--- |
| **@点名** | 随时可用。输入 `@` 弹出成员浮层，被点名者**必定发言**；编排者仍会用剩下的名额补充其他角色——所以 @ 的效果是「**保证它说**」，而不是「只有它说」。三种发言顺序下都有效。 |
| **编排者决定**（默认） | 编排者用「辅助任务模型」读取最近的群聊记录（条数可调）后返回该发言的成员。它同时参考**发言次数统计**（每人最近说了几次、距今多远），避免某位角色话最多就一直由它说下去。 |
| **轮流发言** | **不调用模型**，按「最久没说话」轮转——省一次请求、出话更快，适合轻松闲聊。 |
| **随机** | **不调用模型**，每轮随机挑人。 |

**旁观模式**：点输入区按钮栏里的「**👀 开始旁观**」（只在群聊下出现），成员们会自己聊起来，你只管看。同一个按钮会变成红色的「**⏹ 停止旁观**」，随时可停；轮数在群聊设置里可设 1~20 或**无限轮**。

**自动接力**：一轮说完后，编排者会再被问一次「有没有人想接着补充」，形成角色之间的对话（轮数可调，`0` = 关闭）。

### 三、发言途中可以插话

群聊正在回复时，你仍然可以继续发言——这叫**插话**：

- 你的补充**立刻进入聊天流**，并在**下一位成员发言前**并入上下文，所以后面的成员能看到它
- 本轮发言结束后会**自动再编排一轮**来回应插话（不受「自动接力」设置限制）
- **正在说话的那位看不到**（它的提示词已经发出去了，无法回溯改写）
- **旁观模式下不支持插话**——那时你是观众，发送按钮保持禁用

可插话期间，发送按钮会有紫色微光呼吸，输入框提示会变成「可以在这里插话，成员们会看到你的补充…」。

### 四、群聊设置

点输入框下方的「**群聊设置**」（群聊下这个按钮会自动改名，打开的是群聊专属弹窗），分为五块：

| 分区 | 内容 |
| :--- | :--- |
| **群聊头像 / 名称** | 圆形群聊头像（点击更换，支持 Cropper 裁剪），显示在左侧智能体档案列表中；群聊名称；<br>以及**🗑️ 清空聊天记录**（二次确认后**硬删除**全部消息，成员与群设置保留） |
| **群空间** | 聊天背景（图片 / 视频，支持裁剪并**实时预览**）、背景音乐（URL / 文件 / 音量） |
| **群成员** | 成员卡片（头像、来源对话、`同步中` / `已脱钩` 状态徽章），可增删成员（2~10 人）。**角色级参数只读**——要改请点成员头像进入它自己的对话设置 |
| **编排策略** | 发言顺序 / 单次最多发言角色（上限 = 群内人数）/ 单次最多发言条数 / 自动接力轮数（0 = 关）/ 允许同一成员连续发言 / 参考历史条数（4~30）/ 旁观模式轮数 |
| **用户画像** | 群聊内的昵称与简介（留空则跟随全局「对话设定」） |

### 五、一些值得知道的设计

- **参数实时继承**：群成员**不存副本**，身上只有一个指向来源对话的 id。每次渲染或发言前实时读取来源设置——所以「改了原对话，群里那位角色立刻跟着变」是天然成立的，不需要任何同步动作。
- **来源对话被删除**：该成员会**转为本地副本**（保留最后一次同步到的设定），继续留在群里正常发言，左侧列表上标注「⚠️ 脱钩 N」。
- **点击成员头像**：直接打开**那位成员自己的「对话设置」**（不会切换当前会话），弹窗标题会带上角色名并附一行说明。改完人设 / 音色 / 模型参数，群聊里立刻生效——形成「看到它说得不对 → 点头像改设定 → 回群继续」的闭环。
- **提示词注入同样生效**：你在「个性化设置 → 提示词注入」里配置的内容，会按**每位成员自己的**角色名与人设渲染后追加到它的系统提示词末尾（与私聊一致）。
- **双击消息**：操作栏支持引用、删除；群聊消息的「播放」使用**该成员继承来的音色**（需要它自己的对话里开启了 TTS）。
- **消息配色**：每位成员一个色相（最多 10 个，沿色环均匀取色），气泡左边框、头像描边与发言人名字都跟着变，人多也能一眼分清谁在说话。
- **流式输出**：与私聊共用同一套流式渲染器——括号（）内的动作描写会在**括号闭合的瞬间**变成斜体，新字符逐块淡入，思考 / 内心OS 面板实时展开，该角色一说完就立刻定稿。
- **群聊 v1 不含**：话题管理、长期记忆、知识库、AI 生图、内隐状态（这些仍是私聊的专属能力）。

## 🚀 WebUI使用技巧

- 新手引导：首次访问会自动弹出 5 步上手引导（可跳过，完成状态记在本地）；随时可在「个性化设置 → 新手引导」重看，或打开「功能地图」按分类浏览全部功能与入口（支持搜索，并可一键定位到界面上的按钮）。**已有对话记录的老用户不会自动弹出**。
- 开启新话题：点击输入框下方的“话题管理”按钮，或使用快捷键 `Ctrl+/`，可自动开启新的话题片段。
- 更改话题简介：点击输入框下方的“话题管理”按钮打开的弹窗中，每个话题卡片可点“生成简介”调用语言模型生成，或点右侧「⋯」菜单里的“编辑摘要”手动修改（菜单中还有“导出 HTML”“删除”两项）
- 调整模型参数：在“对话设置”中可为每个对话独立调整温度、Top-P 、上下文长度等等，实现不同风格的回复。
- 语音输入：点击“语音输入”按钮，在 HTTPS 或 localhost 环境下即可使用麦克风转文字（需要浏览器支持）。
- 文件上传：支持上传 `.txt`、`.md`、`.json` 等文本文件以及`.jpg`、`.png`等图片文件（需要模型支持识别图片），可直接将文件拖入网页中，内容将自动附加到消息中发送给模型。
- 消息操作：双击任意消息气泡，弹出操作栏可进行引用、删除、重新生成（AI 消息）或继续生成（AI 消息）等操作。
- 搜索功能：点击右上角圆形搜索按钮，输入关键词即可搜索所有会话的消息和会话标题，点击结果快速跳转。
- 导出与导入：在左侧历史列表点击会话旁的“···”菜单，可选择导出为 JSON 或 HTML；导入统一走侧边栏底部的「**新建角色**」按钮——在弹出的小窗里选择「导入角色卡 / 对话存档」，即可恢复之前导出的 JSON 会话，也可导入 SillyTavern 社区标准角色卡（PNG/JSON，导入后确认角色信息并裁剪头像）。
- 长期记忆：在“个性化设置” -> “记忆”面板可查看记忆条目与活跃度（A 值），支持编辑、删除、固定、恢复归档、手动添加（可归属当前角色或全局），并可查看提取/命中/注入三类日志。反复提及的话题记忆会升温，长期不提及会自动休眠/归档，再次提及可唤醒并注入对话；每个角色的记忆相互隔离，全局记忆（用户喜好）对所有角色生效。

- 提示词注入与宏：在“个性化设置” -> “提示词注入”面板可增删改注入提示词，其中内置「角色内心OS输出」选项（开启后角色先输出内心独白再回复，显示为可折叠面板）；自定义提示词与导入的角色卡提示词均支持 SillyTavern 宏（如 `{{char}}`、`{{user}}`、`{{random}}`、`{{roll}}`、`{{//注释}}`），动态宏随对话每轮实时解析。
- 内隐状态（AI 人格深度）：打开「对话设置」→「内隐状态」勾选**启用**，卡片立刻出现（可拖动/折叠，**卡片只读**）。开启后同一区块会列出该角色所有可编辑状态字段（好感度、信任度、情绪、精力、着装、姿态、所在、关系、未说出口、标记），可直接改值、勾选「注入」（是否把它发给 AI）、勾选「锁」（AI 不再改动该字段）。其中**情绪**是「输入框 + 常用…下拉」：直接敲任意情绪词，或从右侧「常用…」里点一个一键填入（平静/开心/害羞/心动…），旁边的 emoji 与强度 1~10 会一起保存（改情绪词时自动补一个合适的 emoji）；「关系」则是固定选项下拉。下方还能看**状态时间线**并回滚到任意一轮（悬浮卡片上的时间线只用于查看）。「字段管理」可禁用内置字段、或新增自定义字段（**「给 AI 的说明」必填**，否则模型不知道该怎么演化它）；删除自定义字段是**硬删除**（定义 + 所有话题里的值 + 时间线记录一起清除，会二次确认）。想换一张卡片位置可双击卡片标题栏复位。
- 多智能体群聊：点侧边栏「新建角色」旁的 👥 按钮，挑 2~10 个角色即可建群；群里可用 `@角色名` 点名，也可以直接点「开始旁观」看 AI 们自己聊。发言途中你还能**插话**，补充会被后续成员看到并触发一轮重新编排。群成员的人设跟随各自的私聊对话实时同步，点成员头像可直达它的设定。（完整说明见「[👥 多智能体群聊](#-多智能体群聊)」）
- 沉浸模式体验：默认快捷键ctrl+shift+f隐藏侧边栏和上边栏，再次按下退出。
- 快捷键自定义：在“个性化设置” -> “快捷键”面板中可修改或恢复默认快捷键。
