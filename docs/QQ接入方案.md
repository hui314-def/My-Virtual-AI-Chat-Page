# QQ 群聊接入方案（第三方协议端路线）

> 📌 **本项目已实现该方案**——配置入口在「个性化设置 → QQ 接入」；
> 安装、配置、触发策略与排错请看 [`QQ桥接服务说明.md`](./QQ桥接服务说明.md)。
> 本文保留为**选型与风险背景**：协议端对比、官方接口限制、封号风险、常见坑。
> 文末「七」说明了本文描述的成品框架路线（AstrBot）与本项目实际实现（自建桥接服务）的差异。

> 目标：让本项目的 AI 角色在 **QQ 群里陪人聊天**，**不改造现有网页**，也不改动任何前后端代码。
> 阅读顺序建议：先看「一、先搞清三件事」→「二、选型」→「三、部署」→「六、避坑清单」。

## 一、先搞清三件事

### 1.1 为什么不能"网页直接接 QQ"

QQ 没有给个人开发者的通用消息接口。要让一个 QQ 号能收发消息，必须有一个程序**以 QQ 客户端身份登录**（协议端），再由业务程序（机器人框架）通过标准协议跟它对话。所以链路一定是三段：

```
QQ 服务器
   ↕  （协议端以客户端身份登录，扫码）
NapCat（协议端 / OneBot 11）
   ↕  （反向 WebSocket，ws://.../ws）
AstrBot（机器人框架：人格、上下文、群管、限流）
   ↕  （OpenAI 兼容 API）
大模型（DeepSeek / 硅基流动 / 通义 / 本地 Ollama ...）
```

本项目**不需要参与**这条链路。QQ 侧的模型请求直接发给模型服务商，跟网页各走各的。网页仍然是你的"角色调试台"——在那里把人设调好，再搬到 QQ。

### 1.2 ⚠️ 封号风险（务必先读）

NapCat 这类协议端属于社区第三方逆向实现，**腾讯官方视其为"外挂软件"，并持续做技术与非技术打击**。已证实的行为检测手段包括：异常登录方式、多地登录、行为节奏异常等。一旦被判定为机器人账号，后果可能是**警告 / 临时封禁 / 限制功能，甚至永久冻结**。

因此请务必遵守：

- **绝对不要用主号**。用一个专门的小号，并且该小号不要绑重要的东西。
- **新号先"养"几天**（正常聊天、加几个群），别注册当天就挂机器人进群刷消息。
- **不要进大群、不要高频回复**。机器人一秒钟回三条，是最明显的特征。
- **出现风控提示立刻停**。停 24~48 小时，降低频率，再决定是否继续。

> 如果你无法接受账号风险，请转走官方路线（QQ 开放平台，个人主体也能入驻，但需要公网 IP + 白名单 + 机器人审核，且不能发 URL 链接）。官方路线零封号风险，代价是功能受限、接入周期以天计。

### 1.3 你需要准备什么

| 项 | 说明 |
|---|---|
| 一台常开机器 | 本机测试可以，但要**保证不关机不睡眠**；长期跑群建议轻量云服务器（约 50 元/月） |
| 一个 QQ 小号 | 手机能扫码登录即可 |
| 一个模型 API Key | **OpenAI 兼容**即可：DeepSeek / 硅基流动 / 通义 / 智谱 / 本地 Ollama 都行。注意：本项目 `.env` 里是数据库和语音图片服务的配置，**不含大模型 Key**，模型配置在前端网页的设置里，需要你自己从服务商拿一个 |
| Docker（推荐） | Windows 装 Docker Desktop；或用 Linux 服务器 |

## 二、选型：为什么是 AstrBot

### 2.1 协议端对比

| 项目 | 结论 |
|---|---|
| **NapCatQQ** | ✅ **首选**。基于 NTQQ 客户端，自带 WebUI 扫码登录，开箱即用，社区教程最多 |
| Lagrange.OneBot / Lagrange.Milky | ✅ 备选。纯 C# 实现，轻量、跨平台、文档好，适合 Linux 服务器 |
| ~~go-cqhttp / QSign~~ | ❌ **已弃用**，不要再用 |

三者都统一说 **OneBot 11 协议**，所以下面的框架可以随时换协议端，不用重写任何东西。

### 2.2 机器人框架对比（群聊场景）

| 框架 | 群聊拟人度 | 功能广度 | 上手难度 | 结论 |
|---|---|---|---|---|
| **AstrBot** | 中（靠人设和提示词） | ⭐ 很广：多平台、插件、WebUI、TTS、图片、知识库、MCP | ⭐ 低 | ✅ **推荐**，群聊够用且配置全在面板里点 |
| **MaiBot** | ⭐ 很高：会学群友口头禅、主动插话、故意打错字 | 窄（只做中文 QQ 群） | 中（资源开销大） | 想要"赛博群友"效果、且机器扛得住时可选 |
| LangBot | 中 | 广（RAG / 知识库最强） | 低 | 以后要做"角色专属知识库问答"时可以换 |
| NoneBot2 / Koishi | 取决于你自己写 | 框架级，全自己写 | 高 | 想深度定制逻辑才考虑 |

**为什么选 AstrBot 而不是 MaiBot**：你要的是"角色在群里陪人聊天"，核心诉求是**人设一致性 + 开箱即用 + 好维护**。AstrBot 的「人格情景」可以整段粘贴角色卡，还有 WebUI 随时改配置、看日志、限制群聊、文本转图片。MaiBot 的拟人度确实更高，但它是"群里的另一个活人"，会主动说话、消耗明显更多 token，也更难控制——不适合第一次接入。

### 2.3 部署位置

| 位置 | 优点 | 缺点 |
|---|---|---|
| 本机 Windows | 免服务器费用，调试方便 | 关机/睡眠 = 机器人掉线；居家宽带 IP 会变 |
| 轻量云服务器（推荐） | 7×24 稳定，公网 IP 固定 | 约 50 元/月 |

> ⚠️ 如果部署在服务器上，**不要把 QQ 号密码给任何第三方**，也不要把 NapCat 的 WebUI 端口（6099）暴露到公网。需要远程访问时用 SSH 隧道（`ssh -L 6099:127.0.0.1:6099 user@server`）。

## 三、部署步骤

### 步骤 0：拿到模型 API

在你的模型服务商后台创建一个 API Key，记下 **Base URL** 和 **模型名**。示例（任选其一）：

| 服务商 | Base URL | 模型名示例 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 硅基流动 | `https://api.siliconflow.cn/v1` | `Qwen/Qwen3-32B` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| 本地 Ollama | `http://host.docker.internal:11434/v1` | `qwen3.5:9b` |

> Ollama 场景注意：地址必须用 `host.docker.internal`（Docker 容器内访问宿主机），并且在宿主机设置 `OLLAMA_ORIGINS=*`。
> 本地 Ollama 是**免费**的，群聊频繁调用不会烧钱，但需要你的显卡扛得住。

### 步骤 1：部署 NapCat（协议端）

**方式 A：Docker（推荐）**

```bash
docker run -d \
  --name napcat \
  --restart always \
  -e NAPCAT_GID=0 \
  -p 6099:6099 \
  -v ./napcat/config:/app/napcat/config \
  -v ./napcat/qq:/app/.config/QQ \
  mlikiowa/napcat-docker:latest
```

**方式 B：Windows 一键脚本（更省事，适合本机测试）**

在 [NapCatQQ Releases](https://github.com/NapNeko/NapCatQQ/releases) 下载官方一键包，运行 `napcat.bat`（或 `launcher.bat`），按提示走。

**登录**：

1. 浏览器打开 `http://127.0.0.1:6099`，用启动时控制台打印的 Token 登录 WebUI。
2. 左侧「网络配置」→ 添加 **WebSocket 客户端**（反向 WS），先留空或随后填 AstrBot 地址，例如 `ws://astrbot:6199/ws`（同 Docker 网络时用容器名；本机裸装则用 `ws://127.0.0.1:6199/ws`）。
3. 「账号」页扫码登录**小号**。

> 协议端登录期间**不要在电脑上同时登录同一个 QQ 的 PC 版**，会互相挤下线。手机端可以同时在线。

### 步骤 2：部署 AstrBot

```bash
docker run -d \
  --name astrbot \
  --restart always \
  -p 6185:6185 \
  -p 6199:6199 \
  -v ./astrbot/data:/AstrBot/data \
  soulter/astrbot:latest
```

浏览器打开 `http://127.0.0.1:6185`，默认账号 `astrbot` / `astrbot`（**首次登录请立刻改密码**）。

> 两个容器要能互相访问：可以用 `docker network create qqnet` 后给两个容器都加 `--network qqnet`，然后用容器名互连。

### 步骤 3：打通 NapCat ↔ AstrBot

**AstrBot 侧**：`配置 → 消息平台 → 新增 → aiocqhttp`

| 配置项 | 值 |
|---|---|
| 启用 | ✅ |
| 反向 WS 主机 | `0.0.0.0` |
| 反向 WS 端口 | `6199` |
| 反向 WS 路径 | `/ws` |
| Token | 留空（同机）或与 NapCat 一致 |

保存后 AstrBot 会重启并监听。然后 `其他配置 → 管理员 ID` 填**你自己的 QQ 号**（用来执行管理指令）。

**NapCat 侧**：`网络配置 → WebSocket 客户端 → 新增`

| 配置项 | 值 |
|---|---|
| 名称 | `astrbot` |
| URL | `ws://astrbot:6199/ws`（同 Docker 网络）或 `ws://127.0.0.1:6199/ws`（同机裸装） |
| 启用 | ✅ |

**验证**：用你自己的 QQ 私聊机器人小号，发送 `/help`。能看到 AstrBot 的指令列表 = 链路通了。

### 步骤 4：接入大模型

`配置 → 服务提供商 → 新增`，类型选 **OpenAI 兼容**（或 DeepSeek / Ollama 等对应类型）：

- API Key：步骤 0 拿到的 Key
- Base URL：步骤 0 记下的地址
- 模型名：步骤 0 记下的模型名

保存后，在 `配置 → 大语言模型` 里设为默认提供商，并建议开启：

| 开关 | 建议 | 原因 |
|---|---|---|
| 识别群员 | ✅ | 让模型知道"谁在说话"，群聊必需 |
| 日期时间系统提示 | ✅ | 角色有时间感，回复更自然 |
| 网页搜索 | 视需要 | 会额外消耗 token |
| 显示网页搜索引用链接 | ❌ | 群里刷链接很破坏氛围 |

### 步骤 5：配置人格（把网页的角色搬到 QQ）

1. 打开你网站的角色卡预设（`角色卡预设/` 目录里），或在网页里导出当前角色设定。
2. AstrBot `配置 → 人格情景 → 新增`：
   - 名称：角色名
   - 人设：粘贴角色卡里的 **人设 / 角色描述** 部分（可以带上外貌、性格、说话口癖）
   - 预设对话：可粘贴角色卡的**示例对话**（这一项对语气模仿帮助很大）
3. 保存并设为默认人格。

**建议在人格末尾追加一段"群聊行为约束"**（网页里的角色卡是按一对一对话写的，直接搬进群会太长、太出戏）：

```text
【群聊行为约束】
- 你在 QQ 群里聊天，不是在写小说。每条回复控制在 80 字以内，一次只说一件事。
- 大部分时候简短回应就好，不要每次都长篇大论，不要每次都反问用户。
- 保持人设的口癖和语气，但不要用大段括号描写动作。
- 不要在回复里输出 URL 链接、Markdown 标题、代码块。
- 不确定的事情就说不知道，不要编造。
```

> 想让 QQ 上的角色和网页上的角色**真正是同一个"人"**（共享长期记忆、知识库、好感度），需要额外做一层适配服务，见「七、以后想升级」。

### 步骤 6：群聊相关设置（最重要的一步）

| 设置 | 建议值 | 说明 |
|---|---|---|
| 触发方式 | **@机器人 或 前缀触发** | 千万别开"全量监听"，否则群里每句话它都想插嘴，又烦又烧钱 |
| 唤醒前缀 | `/`、角色名 | 例如喊角色名才回应 |
| 群聊白名单 | 只开你信任的 1~2 个群 | AstrBot 支持按群配置路由，未列出的群走"ban"配置 |
| 文本转图片（t2i） | ✅ **建议开** | QQ 单条消息有长度限制，长回复会被切成多段刷屏；转成图片好看且不刷屏 |
| 速率限制 | 开启，每人 3~5 秒一次 | 防止有人连点触发风控 |
| 关键词过滤 / 内容审核 | 建议开 | 避免角色说出违规内容导致账号被处理 |
| 上下文轮数 | 6~10 轮 | 群里人多话题杂，上下文太长既贵又容易串味 |

**私聊**：建议只对你的管理员账号开放，或直接关闭——陌生人私聊机器人是最容易被举报的行为。

### 步骤 7：验收测试

1. 私聊 `/help` → 有指令列表。
2. 私聊角色名 / 前缀 → 角色用**正确的语气**回复。
3. 拉一个小号建测试群（3 人以内）→ @机器人 → 有回复。
4. 连发 5 条消息 → 回复**不刷屏**、**有条数限制**。
5. 让角色回复一条 300 字以上的内容 → 确认被转成图片而不是刷屏 8 段。
6. 关掉电脑睡一晚 / 重启服务器 → 确认 `--restart always` 生效，机器人自动上线。

全部通过，再拉进真正的群。

## 四、角色一致性：QQ 和网页怎么对齐

因为不改网页，两边是**两套独立配置**。要在 QQ 上复刻网页角色的手感，注意：

| 维度 | 网页（本项目的做法） | QQ（AstrBot） |
|---|---|---|
| 人设 | 角色卡 + SillyTavern 宏 | 人格情景，宏不生效（AstrBot 不解析 `{{char}}` 这类宏）→ **粘贴前先把宏替换成实际文本** |
| 上下文 | IndexedDB 本地存，话题分段 | AstrBot 自己的会话上下文，按群/按人隔离 |
| 长期记忆 | DMAE 记忆系统（提取 / 注入 / 话题级隔离） | ❌ 没有。只能靠人格描述里写死设定 |
| 知识库 | 本地 chroma 向量库 | ❌ 不共用。AstrBot 有自己的知识库（需单独喂） |
| 内隐状态（好感度等） | 每话题独立演化 | ❌ 没有，可考虑用插件或放弃 |

**实践建议**：把网页当"试镜间"——想改人设，先在网页上和角色聊几轮，觉得语气对了，再把那段设定复制到 AstrBot。这样比在 QQ 里反复试要快得多。

> 想让 QQ 也吃到网页的宏和记忆：AstrBot 支持装插件，理论上可以写一个插件在发送前做宏替换、调你后端的记忆接口。这属于「七」的范畴。

## 五、成本估算

以 AstrBot + 一个中等活跃群（每天 100 轮对话）为例：

| 项 | 费用 |
|---|---|
| 服务器（可选） | ~50 元/月 |
| 模型 API（DeepSeek 等） | 约 5~20 元/月 |
| 本地 Ollama | 0 元（用自家显卡） |
| NapCat / AstrBot | 0 元（开源） |

**省 token 的三个关键设置**：触发方式（只响应 @）、上下文轮数（6~10 轮）、速率限制。不开这三项，一个月烧掉几十上百块很轻松。

## 六、避坑清单（血泪前人的笔记）

### 6.1 登录与连接

| 现象 | 原因 | 处理 |
|---|---|---|
| 电脑上的 QQ 被挤下线 | 协议端占用了 PC 端协议 | 不要同时登录同一 QQ 的 PC 版；手机端可以 |
| 隔几天就掉线要重新扫码 | QQ 的登录策略要求定期重新登录 | 正常现象。保留 `qq` 数据卷/目录，重扫一次即可，不用重新配置 |
| 扫码看不到二维码 | WebUI 图片渲染问题 | 到 NapCat 的 `data` 目录下找二维码图片文件 |
| 容器之间连不上 | 网络不通 | 同机用 `127.0.0.1`，跨容器用容器名 + 同一个 Docker network；**不含 `http://` 前缀**，协议是 `ws://` |
| 频繁报"戳一戳"失败 | NTQQ 协议部分版本不支持该功能 | 在 NapCat 或框架设置里**关闭「启用戳一戳」**，否则日志一直报错 |
| 「机器人去火星了」/ 无响应 | 反向 WS 配置或 Token 不对 | 核对 URL 路径必须以 `/ws` 结尾；核对两边 Token 一致 |

### 6.2 风控与账号

| 现象 | 原因 | 处理 |
|---|---|---|
| 收到安全提醒 / 被限制发言 | 账号行为疑似机器人 | 立即停止，静默 24~48 小时，回来降低频率 |
| 小号刚挂上就被冻结 | 新号 + 异常登录 | 用小号前先"养号"几天，别当天挂机器人 |
| 群里被举报 | 机器人发广告 / 违规内容 | 开关键词过滤与内容审核；别让机器人发链接 |
| 群里被骂"机器人好烦" | 回复太频繁、太长 | 收窄触发方式、加速率限制、开 t2i |

### 6.3 体验

| 现象 | 处理 |
|---|---|
| 一条长回复刷屏成好几段 | 开启「文本转图片」 |
| 群里回复串味、答非所问 | 缩短上下文轮数；开启「识别群员」 |
| 角色语气不像网页里那个 | 把宏替换成实际文本；补充「预设对话」；追加群聊行为约束 |
| 回复太长像在写小说 | 在人格约束里明确字数上限（见步骤 5） |

### 6.4 维护

- 两个容器都加 `--restart always`，否则机器重启后机器人不会自己回来。
- 定期（1~2 个月）更新 NapCat 与 AstrBot 镜像：腾讯改协议后旧版会失效。
- NapCat 的 6099 端口**不要暴露公网**；远程用 SSH 隧道。
- 关注 AstrBot 面板日志页，出问题第一眼看日志。

## 七、以后想升级的话

如果哪天你觉得"QQ 上的角色和网页上不是同一个人"这件事不能忍，可以在这套架构上再加一层适配服务，让 QQ 侧的会话真正走你本项目的角色体系：

```
NapCat ──OneBot 11──> 自建适配层（Python，200~300 行）
                          ├─ 读角色卡 / 宏解析
                          ├─ 调长期记忆接口（记忆提取 + 注入）
                          ├─ 调知识库检索（chroma）
                          └─ 调模型 → 回复
```

可以做出来的效果：

- QQ 上的对话也进 `chat_store`，**手机 QQ 和网页看到同一份聊天记录**，换设备不断线。
- 长期记忆（好感度、关系阶段、未说出口的事）在 QQ 里也生效，真正做到"跨平台是同一个角色"。
- 复用你已经写好的 `tts`（角色语音）、`image_gen`（场景图）——QQ 上发语音和图片，体验比纯文字强很多。

代价：需要给后端补几个供 QQ 侧调用的接口（带鉴权），并处理 QQ 的消息长度限制、语音格式、并发会话隔离。工程量约 1~3 天。

**当前阶段不需要做这一步**——先让方案跑起来，在真实群里观察几周，觉得确实缺"记忆"和"跨端同步"再回来升级。

### 7.1 本项目实际采用的路线（已实现）

上面这条"自建适配层"就是本项目最终落地的 **方案 B**，但比当时的设想更完整：

| 维度 | 成品框架（AstrBot，本文第三～六节） | 本项目实现（`backend_code/qq_bot/`） |
|---|---|---|
| 部署 | 两个 Docker 容器 | 一个 Python 服务（复用项目已有 fastapi/uvicorn） |
| 角色人设 | 手动粘贴到面板 | **直接继承角色卡**（人设 / 附加系统设定 / 示例对话 + SillyTavern 宏） |
| 模型参数 | 面板里另设一遍 | **继承角色的** 温度 / top_p / max token |
| 知识库 | 需另行喂 | **复用网页同一套 Chroma**，不用重灌 |
| 语音 | 有 | **复用项目 `tts`**，音色取角色设置 |
| 触发策略 | 面板开关 | 自建三层闸门（@ / 冷却配额 / 抖动），配额为硬上限 |
| 灵活性 | 受框架限制 | 想加记忆注入、图片、多角色都可自己改 |

代价：需要自己写代码（本项目已完成），且框架自带的插件生态用不上。

**实际配置入口**：个性化设置 → QQ 接入。
详见 [`QQ桥接服务说明.md`](./QQ桥接服务说明.md)。

### 7.2 仍然值得保留的成品框架场景

- 想接**多个平台**（Telegram / 飞书 / 微信 / Discord），AstrBot、LangBot 的多平台适配器更省事。
- 想要**丰富的现成插件**（点歌 / 天气 / 查询），成品框架的插件生态更成熟。
- 不想写任何代码、也不在乎角色卡能否继承时，AstrBot + NapCat 半小时能上线。
